# Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a static Astro site in `site/` with four parts: a wall of all 26 themes, a theme switcher page whose mock VS Code window is coloured from the shipped theme files, Docs, and Release notes. It deploys to GitHub Pages.

**Architecture:** All theme-dependent styling is generated at build time as CSS keyed by `html[data-theme="<name>"]`. Switching a theme sets that attribute and swaps the Bootswatch `<link>`. No theme JSON ships to the browser. Shiki tokenises each sample once against all 26 themes; tokens with the same colour across every theme share a class, which keeps the HTML small. Pure TypeScript modules in `site/src/lib/` hold the logic and are unit-tested with Vitest. The `.astro` files stay thin.

**Tech Stack:** Astro **7.3.5**, Shiki **4.5.0**, Vitest **5.0.3** (exact pins; each was at least two weeks old on 2026-10-19). Node 24 (`node >=22.22` is required by Astro 7). TypeScript.

**Spec:** `docs/superpowers/specs/2026-10-19-docs-site-design.md`

**Paths:** `SUITE = /Volumes/Dev/vs-code-themes/narcisolobo.bootswatch-1.0.0`; the site lives at `SUITE/site`. Run the tests from `SUITE/site` with `npx vitest run`. The planner knows Astro through v5. If an Astro 7 API differs from what a step assumes (config keys, Markdown imports, `import.meta.env.BASE_URL`), follow the current Astro docs and record a ledger ruling.

## Global Constraints

- **Default theme is `superhero`.** The site opens in it, and it is the fallback whenever no valid theme is named or stored.
- **Bootswatch CSS URL, pinned:** `https://cdn.jsdelivr.net/npm/bootswatch@5.3.8/dist/<name>/bootstrap.min.css`
- **Accuracy:** all code colours come from Shiki and the files in `SUITE/themes/`. All editor-chrome colours come from the same files. No hand-picked colours, no screenshots.
- **Highlighting:** TextMate via Shiki, plus bracket-pair colours from `editorBracketHighlight.foreground1`–`6`, cycling by nesting depth. No semantic highlighting.
- Theme data is read from `../themes/` and `../package.json` at build time, never copied.
- Static output only, under a project-Pages base path `/<repo>/`.
- **Footer credit text:** `Themes based on Bootswatch by Thomas Park, MIT License.`, linking to `https://bootswatch.com`.
- **Usable at phone width (375px) and on a projector:** no horizontal page scroll.

## Review Focus

1. **Stale or garbage theme names:** a `#nonsense` hash, or a stored theme that no longer exists, falls back to `superhero` silently. Test in Task 4.
2. **Storage blocked** (private window, blocked site data): picking a theme still works for the session, and nothing throws. Test in Task 4.
3. **Base path:** every internal link and asset in the built site starts with the configured base. A root-relative `href="/…"` breaks on project Pages. Test in Task 7.
4. **Arrow keys while a form control has focus:** ← or → inside the theme `<select>` (or any input) must not also trigger the page's flip-theme shortcut. Test in Task 4.
5. **A theme file missing an optional colour key:** the generated CSS uses a fallback and never emits `undefined`. Test in Task 2.

### Task 3: Sample highlighting across 26 themes, with bracket pairs

**Files:**
- Create: `site/src/lib/highlight.ts`, `site/test/highlight.test.ts`, `site/src/samples/` (copies of `/Volumes/Dev/vs-code-themes/token-samples/` `sample.tsx`, `sample.css`, `sample.html`, `sample.md`, `sample.json`, `sample.py`)

**Interfaces:**
- Consumes: `ThemeInfo`
- Produces:
  - `type Sample = { id: string; file: string; lang: string; code: string }`, where `id` is `tsx`, `css` and so on, and `file` is the tab label, e.g. `swatch.tsx`.
  - `SAMPLES: Sample[]`, read from `src/samples/`, in this order with these tab labels: tsx `swatch.tsx`, css `theme.css`, html `index.html`, md `README.md`, json `package.json`, py `colors.py`.
  - `renderSamples(samples: Sample[], themes: ThemeInfo[]): Promise<{ html: Record<string, string>; css: string }>`
    - `html[id]` is a `<pre class="code">` with one `<span class="ln">` line number per line. Tokens are `<span class="tN">`.
    - `css` holds rules of the form `html[data-theme="<name>"] .tN{color:…;font-style:…}`.
    - Classes are deduplicated: two tokens whose (colour, font style) match in **every** theme share a class.
  - **Bracket pairs:** `(`, `[` and `{` outside strings and comments open a pair. Depth d (0-based) takes `editorBracketHighlight.foreground{(d % 6) + 1}`, and the closing bracket takes the same colour as its opener. An unmatched closing bracket keeps its plain token colour. A punctuation token that holds several characters, such as `({`, is split so each bracket gets its own span.
  - Approach: Shiki `createHighlighter({ themes: <26 theme JSONs>, langs })`, then `codeToTokensWithThemes` (per-theme variants), plus whatever scope information is needed to tell strings and comments apart.

- [ ] **Step 1: Write the failing tests**

  expect(rule("(")).toBe(sh.colors["editorBracketHighlight.foreground1"]);
  expect(rule("[")).toBe(sh.colors["editorBracketHighlight.foreground2"]);
  expect(rule("{")).toBe(sh.colors["editorBracketHighlight.foreground3"]);

  expect(rule(")")).toBe(rule("("));
